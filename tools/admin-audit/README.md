# Проверка админки и сети сайтов

Набор скриптов, которым проверялась админ-панель перед передачей её сотрудникам
(август 2026). Гоняет ~950 проверок: права ролей, CRUD, связи между вкладками,
интерфейс в браузере, все сайты сети, объём данных, доставку заявок.

Внешних зависимостей нет — только Node 26 (`fetch` и `node:sqlite` встроены).
Браузерные фазы используют Puppeteer из MCP-сервера; путь можно переопределить
переменной `PUPPETEER_PATH`.

## Перед запуском

Скрипты работают против **локально поднятых** копий сайтов, а не против боя.
Сначала снимите резервные копии баз, они будут изменяться:

```
mkdir -p /tmp/db-backup
```
```
for s in main design webdesign python minecraft roblox frontend construct scratch; do cp sites/$s/data/$s.db /tmp/db-backup/$s.db; done
```

Затем поднимите сайты, каждый на своём порту:

```
cd sites/main && PORT=3100 SUPERADMIN_TOKEN=test_super_token_0123456789abcdef0123456789abcdef ALLOWED_ORIGIN=http://localhost:3100 node server/server.js
```

Остальные — на 3101–3110 в том же порядке, в котором они перечислены в
`phase5b-sites.js` (design, webdesign, python, minecraft, roblox, frontend,
construct, scratch, blog, 3dsmax).

Создайте тестовых сотрудников всех ролей — фазы берут их токены из `tokens.json`:

```
node setup.js
```

## Запуск

| Скрипт | Что проверяет | Проверок |
|---|---|---|
| `phase2-security.js` | права ролей по всем эндпоинтам, инъекции, утечки, лимиты | 263 |
| `phase3-crud.js` | создание/чтение/изменение/удаление и валидацию по всем таблицам | 75 |
| `phase4-relations.js` | связи: заявка→клиент, оплаты, зарплата, сироты после удаления | 33 |
| `phase5-ui.js` | все вкладки и модальные окна под тремя ролями в браузере | 132 |
| `phase5b-sites.js` | контентные вкладки на всех девяти сайтах переключателя | 189 |
| `phase6b-perf.js` | скорость на объёме и одновременную работу сотрудников | 20 |
| `phase7-verify.js` | подтверждение отдельных находок в живом интерфейсе | 12 |
| `phase8-admin-removal.js` | единственность админки и редиректы с остальных сайтов | 154 |
| `phase9-lead-delivery.js` | доставку заявок с каждого лендинга в общую CRM | 107 |

Каждый пишет отчёт `report-<фаза>.json` рядом с собой и печатает сводку.
Проверки помечены важностью: `blocker`, `high`, `medium`, `low`, `info`.

`seed-direct.js` наполняет базу объёмом (300 клиентов, 500 заявок, посещаемость
за месяц) напрямую, минуя ограничение частоты запросов — нужен перед `phase6b`.

## Проверка боевой панели

`prod-ui-check.js` открывает **боевую** админку в браузере и только читает:
проходит по вкладкам, смотрит реальные данные, ловит ошибки консоли и упавшие
запросы. Ничего не создаёт и не меняет.

Токен кладётся в `prod-token.txt` рядом со скриптом и **удаляется сразу после
прогона** — это боевой доступ ко всей сети.

## После прогона

Верните базы из копий — фазы оставляют тестовые записи:

```
for s in main design webdesign python minecraft roblox frontend construct scratch; do cp /tmp/db-backup/$s.db sites/$s/data/$s.db; done
```

## Что важно помнить

- Тесты, которые пишут в базу, чистят за собой, но `phase6b` оставляет объём —
  восстановление копий обязательно.
- `phase2` намеренно упирается в ограничение частоты публичной формы; на боевом
  сервере её запускать нельзя — создаст реальные заявки и разошлёт письма.
- Демо-данные отличаются от боевых: часть дефектов (например, утечка скрытых
  курсов через `?all=1`) видна только на копии реальной базы, где такие записи
  есть. Перед важной приёмкой прогоняйте на снимке боевой базы.
